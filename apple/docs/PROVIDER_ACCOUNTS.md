# Provider accounts and event controls

Reviewed against official documentation on 2026-10-02. Open **Destinations → Provider Accounts and Events**. Stream bundles no OAuth application ID or application secret. Use your own registered application and eligible account; a stored credential is not proof of current API permission or public broadcast acceptance.

| Provider | Authorization and discovery | Native actions | External / unavailable actions |
| --- | --- | --- | --- |
| YouTube | Google **Desktop** OAuth client, system browser, PKCE S256 and random-port IPv4 loopback. Enable YouTube Data API v3 and configure consent/test users/verification. Discovery reads the OAuth-selected channel, paginated upcoming broadcasts and owned stream metadata. | Create event (title, description, privacy, absolute scheduled start); edit an upcoming event's title/description/start/privacy; deliberately upload its JPEG/PNG thumbnail (product ceiling 2 MiB and 4096 pixels per side);  delete upcoming event; create an RTMP stream with an explicit profile/reuse setting; separately review and bind an owned upcoming event to an inactive/ready stream; import bound RTMP/RTMPS ingest into a **disabled** destination draft; refresh known event status/viewers, open/copy public URL; explicitly complete a live event; manually connect owned live public chat with the shared account. | Live enablement, early/public start, threaded chat replies. Imported keys/endpoints remain in the destination editor's memory until **Apply Destinations**, then only in stable destination-ID Keychain accounts. An imported destination starts disabled. Project configuration saves provider/channel/event routing IDs only; exported projects and recovery documents contain no access/refresh tokens, client secrets or ingest credentials. Reusable Google/Twitch account tokens use `com.joeblau.Stream.mac.providerAccounts`. macOS Restream uses `com.joeblau.Stream.mac.restream`; its one-time read-and-copy migration preserves `com.joeblau.Stream.restream` for legacy/iOS users. A machine migration flag recorded before copying, plus a Keychain marker when writable, prevents sign-out from resurrecting legacy tokens. If an initial Keychain copy fails, repair the missing values through explicit authorization rather than retrying legacy tokens automatically. This change does not remove the legacy signing access-group entitlement.

**Disconnect Ingest** and **Stop Local** stop local publishing without a remote completion API request; local recording continues. **End Remote** freshly verifies an owned YouTube live event and sends one separately confirmed completion request while other publishers and recording continue. **End Both / End All** retain independent local/remote receipts and explicit unsupported or uncertain remote state. Optional outro uses the shared scene Select/Take and transition path, cancelling delayed actions when Program or captured sessions change. See [clean ending, runtime hooks and acceptance limits](CLEAN_ENDING.md). Each destination displays actual local publisher connection acknowledgment, available bitrate and acknowledged elapsed time. Remote readings are separate, timestamped, expire after 60 seconds, and become unknown/unavailable after failure. There is no synthetic viewer zero or downstream LIVE status.

Every event mutation is sent once. A cancellation or lost reply cannot undo an already accepted remote change; refresh before creating again after an uncertain result. Create retains the actual acknowledged event/stream ID synchronously before any later operation. Upcoming refresh deduplicates stable IDs and never creates, starts or replays events. An acknowledged ID absent from a subsequent upcoming list remains cached with unknown state; use **Verify Selected Event** rather than guessing that it ended or creating a duplicate. The volatile discovery cache is capped at 2,000 event records. Selected routing IDs persist when a destination is applied. Thumbnail uploads require an explicit file selection and confirmation, verify current owned upcoming event identity, and send one raw-media POST. Only a valid provider acknowledgement shows an upload receipt; cancellation/uncertain replies never replay the upload. Images are not retained in portable data.

The existing YouTube event reads also map `contentDetails.latencyPreference`: normal, low or ultra-low. Missing, malformed or unfamiliar values show **Unknown**; this is the provider's setting, not measured delivery latency. **Public thumbnail links** exposes up to eight documented image sizes and returned dimensions without downloading images. Descriptors accept bounded HTTPS links on `ytimg.com` / `googleusercontent.com` host families, with no user information, port or fragment; only public `sqp` / `rs` image query parameters are retained. Unsupported URLs or malformed/out-of-range dimensions are omitted. Missing dimensions remain unavailable. This conservative URL policy can omit a new provider URL shape; it never substitutes an inferred image URL. Thumbnail URLs and latency metadata remain in discovery memory and are excluded from pending repair catalogs, portable destination bindings and recovery documents. Existing event Codable documents decode without these optional fields; decoding new descriptors enforces the same URL, dimension and count bounds.

**YouTube stream setup:** create/select an event, open **YouTube stream and event binding**, and deliberately create a stream or refresh/select an existing stream. Both resolution and frame rate default to variable; if choosing explicit values, match them to the intended destination profile. Stream creation fixes ingestion type to RTMP and sends the chosen reusable setting; it neither starts output nor changes local encoders. Stream metadata excludes ingestion keys/endpoints and caption URLs. The existing import path alone passes bound ingest credentials into the Keychain-backed disabled destination draft.

**Review Binding** freshly reads the owned upcoming event and owned inactive/ready RTMP stream. Its confirmation displays exact IDs, previous binding and automatic settings. Replacing another stream requires a separate unchecked opt-in. Before the single bodyless bind POST, Stream rechecks the reviewed previous binding and automatic settings; changes invalidate the review. An existing matching binding uses fresh reads and an observation receipt. Stream never sends an unbind request, automatically starts a broadcast or recreates a stream after bind failure. These are client-side preflight checks; the API does not provide a documented atomic compare-and-bind guarantee against simultaneous external edits. Review the provider after an uncertain response.

Project-local **provider-pending.json** retains at most 128 acknowledged event/stream repair entries, containing only provider/channel/resource IDs, bounded public title, optional privacy and scheduled time. Remote lifecycle, stream credentials, endpoints, action queues and receipts are excluded. On restart/profile switch, cached event/stream state is unknown and no request is replayed. A fresh owner/state read is required before binding or writing a restored event. The catalog is not part of portable export; use the displayed public repair IDs and fresh provider discovery on another machine. Unsupported, invalid or oversized (over 512 KiB) catalog files are preserved and block new creation. If an atomic save fails after acknowledgement, the ID remains in memory, the UI asks you to copy it before leaving the project, and further creation is disabled. **Forget Local ID** affects only this project cache, with separate confirmation. Partial multi-provider scheduling and provider-specific external/manual workflows remain open work.

OAuth token refresh coalesces concurrent requests, saves rotated refresh tokens, and rejects late replies after disconnect/client replacement. Revoked refresh grants require reauthorization. Read-only requests may retry once after 401; mutations never retry automatically. Rate/quota errors produce allowlisted messages and an API cooldown (`Retry-After`, or 60 seconds when unavailable). Permission/eligibility/approval errors offer repair without echoing response bodies. Desktop HTTP rejects redirects and caps API bodies at 2 MiB; OAuth parsers accept at most 64 KiB. Direct YouTube/Twitch public readers share this credential boundary and require an explicit Read Public Chat action; account authorization and ingest connection never imply an active chat reader. See [direct chat capabilities and validation](DIRECT_CHAT.md).

## Official evidence

- [Google native/desktop OAuth](https://developers.google.com/identity/protocols/oauth2/native-app) documents external-browser authorization, loopback callbacks, PKCE and optional client secret for installed-app token exchange/refresh. A desktop cannot keep a bundled confidential client secret. [Loopback migration](https://developers.google.com/identity/protocols/oauth2/resources/loopback-migration) distinguishes supported desktop clients from deprecated mobile flows.
- [YouTube broadcast list](https://developers.google.com/youtube/v3/live/docs/liveBroadcasts/list), [create](https://developers.google.com/youtube/v3/live/docs/liveBroadcasts/insert), [update](https://developers.google.com/youtube/v3/live/docs/liveBroadcasts/update), [delete](https://developers.google.com/youtube/v3/live/docs/liveBroadcasts/delete), [transition](https://developers.google.com/youtube/v3/live/docs/liveBroadcasts/transition), and [live stream fields](https://developers.google.com/youtube/v3/live/docs/liveStreams) define implemented requests and bound ingestion credentials. Update overwrites mutable fields in requested parts; Stream reads/merges writable snippet fields with an ETag and writes privacy only when explicitly selected and leaves content details outside the update. Live enablement and quota/permissions can still reject an authenticated request.
- [Broadcast resource properties](https://developers.google.com/youtube/v3/live/docs/liveBroadcasts) define the string `latencyPreference` values and the `snippet.thumbnails` URL/unsigned dimension fields, including default/medium/high/standard/maxres/fhd/qhd/uhd image sizes. Stream reads these optional public fields; it does not change latency settings or infer unsupported metadata for other providers.
- [Stream insert](https://developers.google.com/youtube/v3/live/docs/liveStreams/insert), [stream list](https://developers.google.com/youtube/v3/live/docs/liveStreams/list), [stream resource](https://developers.google.com/youtube/v3/live/docs/liveStreams) and [broadcast bind](https://developers.google.com/youtube/v3/live/docs/liveBroadcasts/bind) define the real stream profile/reuse fields, owned list/ID reads, readiness states and bodyless binding request. The variable profile requires both resolution and frame rate to be variable. A reusable stream can support multiple broadcasts; readiness alone does not qualify real ingest/client compatibility.
- [Twitch OAuth flows](https://dev.twitch.tv/docs/authentication/getting-tokens-oauth/) documents public-client device authorization and refresh without a secret; [token validation](https://dev.twitch.tv/docs/authentication/validate-tokens/) requires startup/hourly checks. [API reference](https://dev.twitch.tv/docs/api/reference) defines current user discovery, stream key, channel title and live viewer data. [Schedules](https://dev.twitch.tv/docs/api/schedule/) are a distinct capability.
- [Restream authorization](https://developers.restream.io/authentication/overview), [authorization dialog](https://developers.restream.io/authentication/authorize-dialog), [channels](https://developers.restream.io/channels/channels) and [upcoming events](https://developers.restream.io/events/upcoming-events) define the implemented read APIs/scopes. Its [event create](https://developers.restream.io/events/event-create) and [destination attachment](https://developers.restream.io/events/event-destination-add) are separate operations, with documented platform-specific restrictions; these writes are not exposed by Stream yet.
- [LinkedIn Live Events](https://learn.microsoft.com/en-us/linkedin/consumer/integrations/live-video/) describes product approval/development versus certified Standard tier and separate member/organization scope families. Its page includes older v2 examples (updated 2023); it is evidence of approval requirements, not certification of current endpoint/version availability. No approved application was available for verification.
- Meta's official [Live Video overview](https://developers.facebook.com/docs/live-video-api/overview) and [Live Video feature reference](https://developers.facebook.com/docs/features-reference/live-video-api/) could not be retrieved in this research environment on the review date. Stream therefore does not invent a current permission list, version or approved live integration from third-party mirrors. Verify with your actual Meta app before implementing/claiming Page API access.

## Validation and limits

`ProviderAPITests` exercises production PKCE/form/callback validation, token parsing/refresh retention, pagination/cycle rejection, stable event ID deduplication, unknown state/viewer absence, permission/quota redaction, event create/edit/complete requests and bound-ingest credential boundaries. `apple/scripts/run_provider_accounts_harness.zsh` compiles production vault, loopback receiver and native account session under Swift 6. It drives real loopback callback sockets and HTTP redirect/oversized-response fixtures, a simulated system-browser response, Google/Twitch HTTP fixtures, public device authorization, scope/validation/discovery, refresh coalescing/rotation/revocation, late-response rejection, GET-only retry, actual acknowledged event receipt and workspace shutdown. Keychain and HTTP are injectable fixture boundaries; the harness does not access the operator's real provider credentials. The full native app builds unsigned.

`ProviderEventMetadataTests` exercises the actual event/list response mapper, all three documented latency values and eight thumbnail sizes, absent/future/malformed metadata, unsafe URL/size rejection, bounded legacy/new Codable documents and independent lifecycle preservation. The native account harness verifies metadata through the shipping AccountSession/Vault, changed discovery results, no image requests, actual pending catalog disk round-trip and portable routing exclusion. Its provider and credential boundaries remain controlled fixtures; these checks do not qualify registered consent or a live provider event.

**YouTubeStreamAPITests** exercises exact stream insert/bind requests, explicit/variable profiles, owned state guards, replacement/change rejection, observed existing bindings, malformed/uncertain responses without retry and legacy event-document compatibility. **apple/scripts/run_provider_scheduling_harness.zsh** compiles the production account/vault/catalog and tests acknowledged IDs before binding, partial bind failure and explicit repair without recreation, restart/project isolation/no replay, read-only grants, closed-runtime/account replacement and noncooperative responses, storage bounds/future preservation and actual disk failure. Run from **apple/**:

These results verify local request/lifecycle behavior, not provider approval, real OAuth consent acceptance, ingest acceptance, live chat availability or public event completion. ## Runtime integration

A `StudioRuntime` retains `ProviderAccountSession(restream: chat.restream, pendingDirectory: DesktopStorage.projectDirectory)`. Inject it with `.environment(\.providerAccounts, runtime.providerAccounts)` beside the other runtime environments. After constructing the account session, call `chat.bindAccounts(providerAccounts)` once. Call `providerAccounts.shutdown()` and `chat.shutdown()` during runtime switch/close. Optional recovery binding can use `providerAccounts.recoveryEvents(activeIDs:destinations:)` to persist known routing event IDs and a freshly verified ended state. Live/upcoming does not claim reconnection eligibility. Machine credentials survive workspace shutdown; explicit **Forget Authorization** removes them. The environment is optional so destination editors in isolated fixtures remain usable. After creating the controller and shared scene dispatcher, call `controller.bindEnding(accounts:providerAccounts,dispatcher:dispatcher,previewProgram:previewProgram)`. Cancel pending ending on lifecycle interruption and shut it down before runtime close/switch. Root workspace integration owns these retained runtime binding points.

Upcoming-event privacy writes use a fresh ETag and preserve category/scheduled-end fields while leaving automatic start/stop untouched. The existing snippet-only API retains its default behavior when privacy is omitted. [YouTube thumbnail media upload](https://developers.google.com/youtube/v3/docs/thumbnails/set) defines the fixed upload endpoint, MIME types and acknowledgement; Stream intentionally applies smaller local image bounds than the service maximum. Custom thumbnail eligibility can still fail after authorization. No live provider request is part of fixture validation.

The pending-directory argument defaults to an in-memory catalog when omitted, including isolated fixtures. Root workspace integration must supply the active project directory so repair IDs survive restart; this isolated change does not edit the workspace. Shutdown permanently closes that account session, blocks further requests and rejects late results. Production graphs create a new session for the selected project.
