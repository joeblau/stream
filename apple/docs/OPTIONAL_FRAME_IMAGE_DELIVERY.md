# Private optional image delivery

Studio monitors and external display output subscribe through stable recipient domains and the frame-delivery broker. A single synchronous admission batch prepares the renderer's four-slot source bank and the recipient's five-slot private bank. The source claim moves to the engine at installation; recipient cancellation cannot close another endpoint's shared source. Converter callbacks receive only completed private frames. The existing Program geometry and clock calls remain authoritative.

The recipient's five-slot ceiling covers one transfer destination, one pending private mailbox frame, one dequeued callback, one pending UI image and one currently displayed image. Additional opaque image/provider holds exhaust that endpoint's existing pool and drop optional frames; they cannot allocate a replacement uncharged pool. Exposed retired banks remain charged. Never-exposed rollback uses the coordinator's real-pool close barrier and authoritative receipt claims.

Monitor eligibility applies the existing 33/66.667/200 ms resource throttle before the broker borrows/copies a source, with no second converter throttle. A latest-image handoff retains one pending CGImage and at most one queued MainActor drain. Each lifecycle closes its handoff and cancellation ticket immediately; image publication also checks the current monitor identity. Known preview geometry intents retain their order, and preparation waits for actual geometry ACK/query before admission. Program geometry uses the publisher owner's authoritative command chain. Fractional geometry uses the renderer's rounded pixel dimensions for private banks.

External output captures the selected feed, destination, profile and display. It waits for prior endpoint removal, admits source/private resources, acknowledges the current broker installation and only then constructs a native surface. Pending startup is cancelable, target edits and stale completions cannot activate it, and failed surface creation cancels the exact acknowledged subscription. The existing presentation mailbox retains one image. Scaling/opaque black letterboxing is completed by the broker's sealed aspect-fit transfer into the admitted target bank; CGImage creation remains explicitly deferred and tied to that private backing.

The approved initial focused proof compiles actual coordinator/broker definitions/sealed conversion and actual image converters/handoff/external controller with a matching full-source StreamCore framework. It uses owned small BGRA samples, owned bitmap CGContext readback, and injected descriptors/memory surfaces with system observation disabled. It constructs no NSApplication, NSWindow, NSScreen, studio/runtime/controller, device graph, camera, mixer or capture. Five retained and rendered CGImages kept all five CV slots occupied; the sixth allocation failed and releasing images permitted same-session reuse. Known colors, opaque letterboxing and original source PTS passed. During a bounded owned MainActor stall, 200 image offers retained one pending image and one queued drain; retired pending images and old external callbacks were refused. Held subscription ACK, cancellation, admission refusal and surface failure exercised the actual external controller.

`OPTIONAL_FRAME_IMAGE_DELIVERY_2026-10-22.json` binds exact initial input/executable/report bytes. This focused proof does not execute CompositionEngine or StreamController, qualify real displays or operator flow, or establish sustained resource/performance limits. Canonical full-source typechecking and the synthetic-engine registration/lifecycle integration proof are separate pending checks. The legacy external-display harness has been adapted to the async API in source only; its native-window/physical branches were not run in this work.
