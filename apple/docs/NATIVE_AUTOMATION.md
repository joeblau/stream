# Native Shortcuts and macOS automation

Stream Studio exposes a selected set of foreground App Intents in its macOS app. They use the active studio's command dispatcher; they do not create another capture/output graph. The deployment floor is macOS 14. App Intents metadata is generated by Xcode when building the app.

| Shortcuts action | Explicit target | Behavior |
| --- | --- | --- |
| Open Stream Studio | None | Launch/focus the one persistent studio window. |
| Get Stream Studio State | Open show profile | Return version 1 JSON with actual output/staged/program states and permission context. |
| Select Stream Studio Scene | Profile and stable scene UUID | Select through the studio's current preview/program policy. |
| Take or Revert Stream Studio Scene | Profile and expected staged scene UUID | Reject if another scene is staged; never select a replacement implicitly. |
| Set Stream Studio Local Output | Open show profile and explicit action | Start/stop local preview or local recording. |
| Set Stream Studio Layer Visibility | Profile, staged scene UUID, layer UUID, desired visibility | Apply show/hide through the same target and lock validation as the studio UI. |

Public stream start, arbitrary dispatcher commands, macro execution, profile switching, and permission grants are outside this native action set. Existing authenticated Local Control remains available for explicitly paired production controllers. A shortcut never chooses the show in the same list position or starts a different active session to repair a stale target.

## Configure and run

Install/register the macOS app, open its intended show profile, and finish or skip the setup guide. In Shortcuts, add an action under Stream Studio. The profile, scene, and staged-layer selectors come from the active runtime. Their serialized IDs include the stable profile directory scope plus resource UUIDs; names are display labels. Scene and layer renames update the selector without changing identity. Deleted resources and resources in another profile cannot resolve to a different target.

For a preparation shortcut, select an Intro scene, then Take with the same expected scene target. For a local recording shortcut, choose explicit Start Local Recording and the desired show profile. Poll Get Stream Studio State if subsequent steps need to wait for an asynchronous output state. A successful start means the command was accepted; its returned `recording` field may still be `preparing`.

All actions declare foreground execution for macOS 14 compatibility and focus the existing studio. Capture-changing actions preflight the microphone and the camera/screen/app-audio sources demanded by the proposed staged/program compositions, including nested scenes and project overlays. Missing grants yield `permissionRequired` with a repair explanation. Automation never calls the permission-request API. Complete permission setup in the visible studio before starting capture. Scene preparation while outputs are idle can proceed without starting capture.

Commands reject while onboarding, a modal/sheet, or an explicit runtime interaction gate is active. The app checks current availability and targets immediately before dispatch. Take, locks, preview/program mode, macro serialization, and output transitions retain their normal dispatcher rules.

No custom AppleScript dictionary or unauthenticated URL command bridge is installed. macOS automation tools can run a user-created shortcut through the system CLI:

```sh
/usr/bin/shortcuts run "Prepare Intro"
```

AppleScript may invoke that same CLI using `do shell script`, or launch/focus the app through macOS Launch Services. To open the studio directly:

```sh
/usr/bin/open -b com.joeblau.StreamMac
```

The CLI/AppleScript path uses the Shortcuts action's existing parameter selections and validation. It does not pass a token, stream key, or public start command through process arguments.

## State and errors

State is a sorted, versioned JSON string with `profileID`, `profileName`, `stream`, `recording`, `preview`, `stagedSceneID`, `programSceneID`, `pendingStagedEdits`, `directLiveEditing`, `permissions`, and `unavailablePermissions`. Permission values are `granted`, `needsRequest`, or `denied`. Output labels report the actual shared state. No connection credentials, destinations, tokens, or media paths appear in this snapshot.

Failures use NSError domain `com.joeblau.StreamMac.Automation`, a stable numeric error code, `StudioErrorCode` in user info, and readable localized text. Codes include `versionMismatch`, `invalidTarget`, `invalidValue`, `runtimeUnavailable`, `profileChanged`, `interactionRequired`, `permissionRequired`, and `unavailable`. A rejected action performs no dispatch. A runtime is allowed five seconds to finish foreground launch; interrupted actions check cancellation and never retry an already dispatched command.

## Runtime integration

Bind `StudioAutomationEndpoint.shared` to the active dispatcher and permission manager when constructing the runtime, with its profile display name and a current staged-layer provider. Entity queries can then resolve before an intent's `perform` call or window appearance. Set `interactionBlocked` during project operations or other embedded interactions that are not native sheets. Unbind before tearing down or restoring a runtime, and bind the new runtime after its profile directory is selected. The endpoint also rejects a directory mismatch during any binding gap. Weak dispatcher/permission references prevent another controller graph from being owned by automation.

## Validation

`zsh apple/scripts/run_studio_automation_harness.zsh` compiles the production request schema, endpoint, and App Intents against a deterministic minimal dispatcher. It exercises typed resource scope, malformed IDs, exclusion of public start, profile/scene/layer rename, deleted scene, setup/interaction/permission gates, fresh dispatcher availability, recording preparation feedback, and switch/unbind/rebind behavior. It uses an isolated UserDefaults suite and does not request OS permissions or access the user's capture devices.

A full StreamMac build also verifies native App Intents compilation and Xcode metadata extraction. Before release, use the installed/signed app in Shortcuts to verify action discovery, selectors, cold launch and closed-window focus, denied/revoked permission repair, exact scene targets after rename/delete, profile switch rejection, and the `shortcuts run` path on macOS 14 and newer supported versions. Those system UI/permission checks are manual qualifications, not results of the deterministic harness.
