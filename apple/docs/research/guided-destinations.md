# Guided manual destinations (#170)

Reviewed 2026-10-02. These guides create disabled native destination drafts, not provider sessions or account grants. No authenticated test credentials were available. Account eligibility, event state and acceptance of the actual Stream encoder remain unverified until the producer tests an issued ingest. The setup sheet requires the producer to confirm their account granted external ingest credentials; it does not infer permission from a provider name or mobile LIVE access.

All guides disclose comments, viewer metrics, scheduling and remote-event state unavailable **in Stream** because no authorized provider API is connected. Provider capabilities can exist separately. Relay ingest follows ordinary destination IDs, Keychain credentials, validation, bounded queues, retries and independent stop; downstream delivery is managed by the relay and cannot be inferred from Stream's ingest acknowledgement.

Generic custom RTMP, RTMPS, SRT and WHIP creation remains available. Attached guides block starts using a protocol they do not document; clearing the guide preserves stable ID, secrets and settings. WHIP is experimental H.264/Opus: Stream cannot supply bearer-header authentication or convert a separate provider key. Use an explicitly issued URL carrying its authorization, otherwise choose RTMPS. SRT is caller-only. Templates use H.264 and editable custom starting limits; they do not mark a documented recommendation as a verified ingest test.

Stream currently emits stereo 48 kHz audio. Instagram's archived guide and [Restream's encoder guideline](https://support.restream.io/en/articles/73108-best-settings-for-your-streaming-software) recommend 44.1 kHz. The native guidance discloses the mismatch. A template cannot certify the provider's required sample rate, H.264 level/profile or strict CBR policy. Stream resizes the same program frame for every destination; compose the program for portrait when required, then verify the actual provider preview for cropping/framing.

Validation on Mac15,8 / macOS 27.0.1 (26A434): Core tests exercise disabled default creation, retained credential validation, backward/future guidance decoding, portable redaction, attached-guide protocol gating and destination-specific settings conversion. The shipping `DestinationOutputController` harness uses X RTMPS and Restream SRT templates with injected publishers to exercise separate converted profiles, routing fields, partial failure, retry with the same ID, stale acknowledgement rejection and independent stop while the other remains live. These are local lifecycle tests, not provider ingest acceptance. Reproduce with `zsh scripts/run_destinations_harness.zsh` and `xcodebuild -project Stream.xcodeproj -scheme StreamCoreTests -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO test -only-testing:StreamCoreTests/DestinationProviderTemplateTests` from `apple/`.

Real provider test events, authorized comments/metrics APIs, relay downstream health and account-specific encoder compliance remain unverified. #132's shared-encoder backend is also still incomplete; each publishing destination retains its own encoder.
